# Frontend API integration

Use the same origin as the application and call `/api`. The development API is also available directly at `http://localhost:8080/api`; Swagger UI is at `/api/docs/`. All examples below assume the `/api` prefix.

1. `POST /sessions` with `username` and `password`. Send the returned `accessToken` as `Authorization: Bearer <accessToken>` for protected requests. `DELETE /sessions` revokes that session; a missing or expired session returns 401. A 503 means revocation could not be confirmed and logout can be retried.
2. `POST /listings` with a unique `Idempotency-Key` header and the initial listing fields. A retry of the same request must use the same key. The response contains the draft ID and `version`.
3. Save edits with `PUT /listings/{id}` and the current `expectedVersion`. A 409 means the listing changed or its current state disallows the operation; reload before resolving the conflict.
4. Create photo metadata with `POST /photos`, then send its bytes to `PUT /photos/{id}/content` as `{ "base64": "..." }`. Only JPEG and PNG up to 20 MiB by default are accepted. The seller can replace a validated image; a failed replacement preserves the current image.
5. Optionally create suggestions with `POST /generations`: provide `listingId`, a unique `requestKey`, the saved `inputVersion`, a `clientRevision` representing the editor contents, and mode `DETERMINISTIC` or `LOCAL`. Deterministic attempts complete immediately when the draft has usable title, description or category; unsupported modes and empty deterministic input return 400. For `LOCAL`, call `POST /generations/{id}/execute` and read the attempt with `GET /generations/{id}`. Do not apply results automatically: compare the latest request and editor revision, then let the seller review and edit them.
6. Publish with `POST /listings/{id}/publications`, body `{ "expectedVersion": 0 }` using the actual current version, and a unique `Idempotency-Key`. Retrying the same publication uses the same key. Required fields and a validated photo must be present.
7. Browse `GET /catalog` and `GET /catalog/{id}` anonymously. Read the published image from `GET /catalog/{id}/photo`. A signed-in buyer sends `POST /interests` with `{ "listingId": "<id>" }`; repeated requests return the existing interest.
8. The seller uses `GET /users/me/listings` for status-filtered listings and `interestCount`, and `GET /users/me/listings/{id}/interests` for buyer display names and timestamps. Archive with `POST /listings/{id}/archives` and the current `expectedVersion`.

Errors use `application/problem+json`. Field validation errors include an `errors` array. If local generation returns 503 with `GENERATION_OUTCOME_UNKNOWN`, keep the editor usable. Repeating `execute` returns the current attempt without another model call; a processing attempt returns 202. Create a new attempt with a new `requestKey` only when the seller explicitly retries. Polling an attempt still processing after 60 seconds marks it `UNKNOWN`. An old or aborted request must not overwrite newer editor contents.

Offset pagination is ordered but can shift when listings change between requests. Interest is a stored signal, not a messaging or payment system. External AI providers and production identity flows remain future work.
